📌 어제 배운 내용과의 연결
어제는 자동화의 일곱 개념을 실제 코드 한 벌로 조립해 1부 심화를 총정리했으니, 오늘부터는 그 코드 파이프라인을 코드 한 줄 없이 화면에서 조립하게 해주는 노코드 도구를 이번에는 실제 설정 화면 수준까지 다시 뜯어봅니다.

🎯 오늘 배울 개념
Zapier·n8n·Make 같은 노코드(No-Code, 코드를 직접 작성하지 않고 화면의 버튼과 블록만으로 프로그램을 만드는 방식) 도구에서 트리거·액션 블록의 입력 필드를 채울 때, 화면 뒤에서 정확히 어떤 API 요청이 자동으로 만들어지는지, 그리고 여러 블록을 조합할 때 데이터가 어떤 모양으로 다음 블록에 전달되는지

━━━━━━━━━━━━━━━━━━━━

9일차에 노코드 도구를 "조립식 미니 공장 키트"에 비유하며, 부품 겉면의 스티커만 보고 이어 붙이면 안쪽 배선은 알 필요 없다고 배웠습니다. 오늘은 그 부품 하나를 실제로 뜯어서 안쪽 배선을 들여다보겠습니다. 예를 들어 "Webhooks by Zapier" 트리거 부품을 뜯어보면, 안쪽에는 특정 주소로 요청이 들어오길 기다리는 서버 하나가 이미 돌아가고 있습니다. 이 주소가 바로 5일차에 배운 웹훅(Webhook, 이벤트가 발생하면 자동으로 알려주는 콜백 방식) 주소이고, 사용자가 화면에서 "트리거: 새 웹훅 받기"를 클릭하는 순간 Zapier는 이 주소를 자동으로 발급해 사용자에게 복사해 가라고 보여줍니다. 이어서 "액션: Google Sheets에 행 추가" 부품을 뜯어보면, 안쪽에는 여러분이 입력 필드에 채운 값(시트 이름, 열 이름 등)을 그대로 담아 Google Sheets API에 요청을 보내는 코드 한 덩어리가 들어 있습니다. 즉 노코드 도구의 설정 화면이란, 4일차에 배운 API 요청의 주소·인증정보·전송값을 여러분이 직접 타이핑하는 대신, 빈칸에 값만 채우면 그 값이 미리 짜인 API 호출 코드 안의 정확한 자리에 자동으로 끼워 넣어지는 서식(양식) 화면인 셈입니다. 조립식 키트의 부품 하나하나는 사실 "특정 API 호출 코드 + 사용자가 채울 빈칸"이 미리 포장되어 있는 상자였던 것입니다.

🛠 실전 연결
이 원리를 여러분의 프로젝트에 그대로 대입하면, Kakao 프록시가 로그인 결과를 돌려줄 때 그 응답을 Zapier의 웹훅 트리거로 받도록 설정할 수 있습니다. 트리거 화면에는 Zapier가 발급한 웹훅 주소 하나만 채우면 되고, 그 주소를 여러분의 크롬 확장이나 서버리스 함수 코드 안에서 한 번 호출하는 줄만 추가하면 연결이 끝납니다. 그다음 액션 블록에서 "Google Sheets에 정산 내역 행 추가"를 선택하면, 여러분이 직접 Google Sheets API 문서를 읽고 인증 토큰을 처리하는 코드를 짤 필요 없이 화면의 빈칸만 채워서 여비 계산기가 쓸 정산 데이터를 자동으로 시트에 쌓아 둘 수 있습니다. 반대로 지금 이 브리핑을 쓰는 Claude Routines처럼 "어제 파일을 읽고 그 내용을 판단해서 오늘 글의 구조를 결정하는" 작업은, 노코드 도구의 빈칸 채우기만으로는 처리할 수 없습니다. 빈칸은 고정된 값이나 이전 블록의 결과값을 그대로 옮기는 정도만 할 수 있을 뿐, "이 파일 내용을 읽고 알맞게 판단해서 새로운 문장을 써라"와 같은 유연한 판단은 카탈로그에 없는 부품이기 때문입니다. 이 부분이 3부에서 다시 다룰 AI 에이전트와 노코드 도구의 결정적인 차이입니다.

🔍 예시
실제 Zapier 화면에서 "카카오 로그인 완료 시 정산 시트에 행을 추가한다"는 Zap을 만든다면 설정 화면은 대략 이렇게 채워집니다.

  1단계 [트리거 선택]
    앱 : Webhooks by Zapier
    이벤트 : Catch Hook
    발급된 웹훅 주소 : https://hooks.zapier.com/hooks/catch/123456/abcdef/

  2단계 [트리거 테스트]
    받은 샘플 데이터 :
      user_name : 홍길동
      amount : 32000
      date : 2026-08-31

  3단계 [액션 선택]
    앱 : Google Sheets
    이벤트 : Create Spreadsheet Row
    스프레드시트 : 여비정산_2026
    시트 : Sheet1
    열 매핑 :
      A열(이름) ← 1단계의 user_name
      B열(금액) ← 1단계의 amount
      C열(날짜) ← 1단계의 date

이 화면에서 사용자가 실제로 하는 일은 주소 복사, 시트 이름 선택, 열 매핑 클릭 몇 번뿐입니다. 하지만 3단계 저장 버튼을 누르는 순간 Zapier 내부에서는 다음과 비슷한 요청이 자동으로 만들어져 실행됩니다.

  요청 주소 : sheets.googleapis.com/v4/spreadsheets/여비정산_2026/values/Sheet1!A:C:append
  인증 헤더 : Zapier가 대신 관리하는 사용자의 구글 토큰
  전송값 : 이름=홍길동, 금액=32000, 날짜=2026-08-31

즉 열 매핑 화면에서 클릭한 결과가 그대로 이 요청의 전송값으로 옮겨진 것뿐이며, 인증 토큰 관리와 API 문서를 읽는 수고는 Zapier가 미리 대신 짜둔 코드가 처리해 준 것입니다.

📝 오늘의 한 줄 정리
노코드 도구의 설정 화면은 API 요청의 주소·인증정보·전송값을 사용자가 직접 코드로 쓰는 대신 빈칸으로 채우게 해주는 서식일 뿐이며, 저장 버튼을 누르는 순간 그 빈칸 값이 미리 짜인 API 호출 코드 안에 그대로 끼워 넣어집니다.

🙋 초보자가 자주 헷갈리는 점
설정 화면에 주소나 인증 정보가 안 보인다고 해서 그런 절차가 아예 생략된 것이라고 오해하기 쉽습니다. 실제로는 여러분이 "구글 계정 연결" 버튼을 눌러 로그인했던 그 순간, Zapier가 여러분을 대신해서 인증 토큰을 이미 발급받아 저장해 둔 것이며, 매 실행마다 그 토큰을 꺼내 요청에 자동으로 끼워 넣고 있는 것입니다. 즉 인증 절차가 없어진 게 아니라, 사용자가 한 번만 대신 처리해 두면 그다음부터는 화면에서 보이지 않게 반복 실행될 뿐입니다.

💬 내일 예고
