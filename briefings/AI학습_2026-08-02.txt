📚 오늘의 학습 주제 : 5일차 · 웹훅(Webhook) — API와 무엇이 다르고 왜 자동화에 필요한가 (2026-08-02)

📌 어제 배운 내용과의 연결
어제는 손님이 주방에 정해진 형식으로 주문을 넣는 API를 배웠으니, 오늘은 반대로 주방이 손님에게 먼저 알려주는 웹훅을 배웁니다.

🎯 오늘 배울 개념
웹훅(Webhook, 이벤트가 발생하면 요청을 받지 않고도 상대방이 먼저 알려주는 콜백 방식의 통신)

━━━━━━━━━━

어제 레스토랑 비유에서 손님은 메뉴판을 보고 종업원에게 주문을 넣고, 요리가 다 되었는지는 손님이 직접 "다 됐나요?"라고 계속 물어봐야 알 수 있었습니다. 이렇게 매번 직접 물어보는 방식을 폴링(Polling, 상태가 바뀌었는지 주기적으로 계속 확인하는 방식)이라고 합니다. 그런데 만약 손님이 예약 전화번호를 남겨두고, 요리가 완성되는 그 순간 주방이 먼저 손님에게 전화를 걸어 "준비됐습니다!"라고 알려준다면 어떨까요? 손님은 더 이상 계속 물어볼 필요 없이, 전화가 올 때까지 다른 일을 하면 됩니다. 이 "먼저 걸려오는 전화"가 바로 웹훅입니다. 웹훅은 이벤트(주문한 요리가 완성됨)가 발생하는 순간, 미리 등록해 둔 주소(전화번호)로 상대방이 알아서 소식을 보내주는 방식입니다.

공장 조립라인 비유로도 이어서 생각해 볼 수 있습니다. 품질 검사 공정에서 불량품이 발견되었을 때, 관리자가 검사 라인 앞을 계속 지키고 서서 "불량 있어요?"라고 매번 확인하는 것이 폴링이고, 대신 불량품이 발견되는 즉시 검사 센서가 관리자의 휴대폰으로 경고 알림을 자동으로 쏘아 보내는 것이 웹훅입니다. 두 방식 모두 결국 "정보를 얻는다"는 결과는 같지만, 누가 먼저 통신을 거는지가 정반대입니다. API 호출은 내가 필요할 때 상대에게 묻는 것이고, 웹훅은 상대에게 일이 생겼을 때 상대가 나에게 알려주는 것입니다.

🛠 실전 연결
지금 이 학습 브리핑을 만드는 세션도 웹훅을 실제로 사용하고 있습니다. 만약 여러분이 GitHub 저장소의 어떤 PR(변경 제안)을 지켜봐 달라고 요청하면, 이 세션은 그 PR을 계속 들여다보며 확인하는 대신 GitHub에 "이 PR에 무슨 일이 생기면 나에게 먼저 알려줘"라고 웹훅을 등록해 둡니다. 그러면 리뷰 댓글이 달리거나 빌드가 실패하는 순간, GitHub가 즉시 그 소식을 세션으로 보내줍니다. Kakao 프록시 사례에서 로그인 콜백(Callback, 어떤 작업이 끝난 뒤 다시 호출되어 결과를 전달하는 방식)도 같은 원리입니다. 여러분의 크롬 확장이 카카오 로그인 결과가 나올 때까지 계속 물어보는 대신, 사용자가 로그인을 완료하는 순간 카카오 서버가 미리 등록해 둔 콜백 주소로 로그인 결과를 먼저 보내줍니다.

🔍 예시
아래는 오늘 이야기한 두 가지 웹훅 사례를 설정 형태로 표현한 것입니다.

GitHub 웹훅 (PR 감시)
  이벤트 : pull_request.opened, issue_comment.created 등
  전달 방식 : 이벤트가 발생하는 즉시 GitHub가 등록된 주소로 알림 전송
  받는 쪽 : 세션에 <github-webhook-activity> 형태로 도착

카카오 로그인 콜백 (Kakao 프록시)
  등록 주소(redirect_uri) : https://my-extension.example/callback
  전달 데이터 :
  {
    "code": "a1b2c3d4",
    "state": "xyz789"
  }

두 경우 모두 우리 쪽 프로그램이 반복해서 물어보는 코드를 짤 필요가 없다는 점이 핵심입니다. 그저 "무슨 일이 생기면 이 주소로 알려줘"라고 한 번 등록해 두기만 하면, 그 뒤로는 이벤트가 생길 때마다 상대방이 알아서 소식을 전해줍니다.

📝 오늘의 한 줄 정리
웹훅은 내가 계속 물어보지 않아도, 이벤트가 생기는 순간 상대방이 먼저 소식을 보내주는 콜백 방식의 통신입니다.

🙋 초보자가 자주 헷갈리는 점
웹훅을 API와 완전히 다른 별도의 기술이라고 오해하기 쉽지만, 사실 웹훅도 내부적으로는 정해진 주소로 정해진 형식의 요청을 보내는 API 호출의 한 형태입니다. 다른 점은 오직 "누가 먼저 통신을 시작하는가"뿐입니다. 손님이 주방에 먼저 연락하면 API, 주방이 손님에게 먼저 연락하면 웹훅이라고 기억하면 됩니다.

💬 내일 예고
내일은 사람이나 이벤트가 아니라 정해진 시각 자체를 트리거로 쓰는 스케줄링(Scheduling)과 예약 실행(cron)을 배웁니다. 매일 아침 이 브리핑이 자동으로 도착하는 것도 바로 이 원리 덕분입니다.
