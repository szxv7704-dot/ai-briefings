📚 오늘의 학습 주제 : 심화 12일차 · Make(구 Integromat)의 라우터(Router)와 번들(Bundle), 하나의 신호를 여러 갈래로 쪼개고 다시 묶는 법 (2026-09-03)

📌 어제 배운 내용과의 연결
어제는 n8n이 반복 노드로 영수증 다섯 장을 컨베이어 벨트처럼 한 장씩 꺼내 같은 검사대(IF 노드) 앞으로 밀어 넣는 과정을 캔버스 위에서 직접 확인했으니, 오늘은 같은 다섯 장의 영수증을 Make(구 Integromat)라는 도구가 번들이라는 단위로 어떻게 다르게 포장해서 옮기는지 살펴봅니다.

🎯 오늘 배울 개념
Make의 시나리오(Scenario, 여러 모듈을 순서대로 연결해 만든 하나의 자동화 흐름 전체)를 구성하는 모듈(Module, 트리거나 액션 하나하나를 나타내는 상자)들 사이를 오가는 데이터의 최소 단위인 번들(Bundle, 시나리오가 한 번 실행될 때 모듈과 모듈 사이를 오가는 데이터 한 덩어리)과, 배열 하나를 여러 개의 번들로 쪼개는 반복기(Iterator, 목록 하나를 낱개 번들 여러 개로 분해하는 모듈), 그리고 조건에 따라 번들이 지나갈 길을 나누는 라우터(Router, 하나의 경로를 여러 갈래로 쪼개고 각 갈래 앞에 필터를 다는 모듈)

━━━━━━━━━━━━━━━━━━━━

어제 n8n의 반복 노드는 전표 뭉치를 올려둔 컨베이어 벨트 그 자체였습니다. 벨트가 돌면서 전표를 한 장씩 검사대 앞으로 밀어 넣고, 검사가 끝나면 다시 벨트로 돌아가 다음 전표를 꺼내는 순환 구조였죠. Make의 반복기는 이 벨트에서 전표를 한 장 집어 올릴 때마다 그 위에 일련번호 스티커, 즉 번들을 붙여 개별 포장 상자에 담아 내보내는 포장 담당자에 가깝습니다. n8n에서는 다섯 장의 전표가 여전히 하나의 목록으로 벨트 위를 돌지만, Make에서는 반복기를 거치는 순간 전표 다섯 장이 각각 독립된 상자 다섯 개가 되어, 그 뒤에 있는 모듈들을 다섯 번 따로따로 통과합니다. 즉 n8n의 벨트가 "목록을 유지한 채 한 바퀴씩 돌리는 방식"이라면, Make의 반복기는 "목록을 아예 낱개 소포로 뜯어서 각각 배송을 시작하는 방식"입니다. 여기에 더해 라우터는 검사대 자체를 다이아몬드 모양의 갈림길 표지판으로 바꿔 놓습니다. n8n의 IF 노드가 참·거짓 두 개의 출구만 가진 검사대였다면, Make의 라우터는 원하는 만큼 경로를 열어 두고 각 경로 입구에 필터(Filter, 그 경로로 들어갈 조건을 정해 두는 검사 규칙)를 따로 붙여, 조건에 맞는 소포만 그 경로로 들여보내고 나머지는 튕겨 냅니다.

🛠 실전 연결
크롬 확장이 출장 하나에 딸린 영수증 다섯 장을 한꺼번에 긁어 Kakao 프록시로 넘기는 같은 상황을 Make로 옮기면 이렇게 그려집니다. 웹훅 모듈이 영수증 다섯 장이 담긴 배열을 통째로 받고, 반복기 모듈이 그 배열을 다섯 개의 번들로 쪼갠 뒤, 라우터가 각 번들을 10만 원 이상 경로와 10만 원 미만 경로 중 하나로 흘려보냅니다. 눈여겨볼 점은 반복기를 통과하는 순간부터 다섯 개의 번들은 서로의 존재를 모르는 별개의 흐름이 되어, 시나리오 한 번 실행이 사실상 뒤에서 다섯 번 반복 실행되는 것과 같아진다는 점입니다. 만약 다섯 장을 합산해서 "이번 출장 총액이 30만 원을 넘었는지"까지 판단하고 싶다면, 반대로 여러 번들을 다시 하나로 묶는 집계기(Aggregator, 여러 번들을 하나의 배열이나 합계 값으로 다시 합치는 모듈)를 라우터 뒤에 붙여야 하는데, 이는 Claude Routines가 승인 알림을 보낼 때 "건별 알림"과 "출장 전체 합계 알림" 중 무엇을 보낼지 정하는 것과 같은 설계 고민입니다.

🔍 예시
Make 시나리오 편집 화면에 위 상황을 옮기면 대략 이렇게 배치됩니다.

  1번 모듈 [Webhook]
    이름 : 영수증 목록 수신
    수신 데이터 : receipts = [ {user:"홍길동", amount:150000}, {user:"홍길동", amount:35000}, ... 총 5건 ]

  2번 모듈 [Iterator]
    Array 필드 : {{1.receipts}}
    동작 : 배열 5건을 번들 5개로 분해, 이후 모듈을 번들마다 한 번씩 실행

  3번 모듈 [Router]
    경로 A 필터 : {{2.amount}} >= 100000
    경로 B 필터 : {{2.amount}} < 100000

  4번 모듈 [Slack] (경로 A)
    채널 : #정산승인
    메시지 : {{2.user}}님이 {{2.amount}}원 정산 승인을 요청했습니다

  5번 모듈 [Google Sheets] (경로 B)
    시트 : 여비정산_2026
    행 추가 : user, amount 값을 각 열에 매핑

여기서 {{2.amount}}처럼 모듈 번호와 필드 이름을 점으로 이어 쓰는 방식은 n8n의 {{$json["amount"]}}와 하는 일은 같지만, "어느 모듈에서 나온 값인지"를 번호로 직접 못 박아 표시한다는 점이 다릅니다.

📝 오늘의 한 줄 정리
Make는 목록 데이터를 반복기로 낱개 번들로 쪼개고 라우터로 여러 갈래에 필터를 달아 흘려보내는 방식이며, n8n이 하나의 목록을 벨트처럼 순환시키는 것과 달리 쪼개진 순간부터 각 번들이 서로 독립된 실행으로 갈라진다는 점이 가장 큰 차이입니다.

🙋 초보자가 자주 헷갈리는 점
반복기(분해)와 라우터(분기)를 같은 갈림길 기능으로 혼동하기 쉽지만, 반복기는 하나의 목록을 여러 개의 독립된 번들로 쪼개는 것이고 라우터는 그렇게 쪼개졌든 아니든 번들 하나가 지나갈 길을 여러 경로 중 하나로 정하는 것이라 서로 다른 단계입니다. 또한 Make는 모듈이 몇 번 실행되었는지를 오퍼레이션(Operation, 모듈 하나가 한 번 실행될 때마다 소모되는 사용량 단위)으로 세어 요금을 매기기 때문에, 반복기로 영수증 다섯 장을 쪼개면 뒤따르는 모듈들이 다섯 번씩 실행되어 오퍼레이션도 다섯 배로 늘어난다는 점을 놓치기 쉽습니다.
