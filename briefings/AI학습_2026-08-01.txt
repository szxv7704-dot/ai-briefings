📚 오늘의 학습 주제 : 4일차 · API란 무엇인가 — 서로 다른 프로그램이 대화하는 방법 (2026-08-01)

📌 어제 배운 내용과의 연결
어제는 여러 트리거와 액션이 사슬처럼 이어진 워크플로우를 배웠으니, 오늘은 그 사슬의 각 연결 고리에서 서로 다른 프로그램들이 실제로 어떤 규칙으로 데이터를 주고받는지를 배웁니다.

🎯 오늘 배울 개념
API(Application Programming Interface, 서로 다른 프로그램이 데이터를 주고받기 위해 미리 정해 놓은 대화 규칙)

━━━━━━━━━━

어제 조립라인 비유에서, 용접 공정의 로봇 팔이 도색 공정의 로봇 팔에게 차체를 넘길 때 아무렇게나 넘기지 않습니다. "차체는 반드시 이 위치에, 이 방향으로, 이 신호와 함께 넘긴다"는 정해진 규격이 있고, 두 로봇 팔은 그 규격만 지키면 서로의 내부 작동 원리를 몰라도 문제없이 협업합니다. API가 바로 이 규격입니다. 프로그램 A가 프로그램 B의 내부 코드를 몰라도, B가 미리 정해 놓은 "이런 형식으로 요청하면 이런 형식으로 답을 준다"는 약속(API)만 따르면 원하는 정보를 주고받을 수 있습니다.

레스토랑에 비유하면 더 쉽습니다. 손님(프로그램 A)은 주방(프로그램 B)에 직접 들어가 요리하지 않습니다. 대신 정해진 메뉴판(API 문서)을 보고 "김치찌개 1인분 주세요"라고 종업원(API)에게 주문하면, 주방은 그 형식에 맞는 요청만 받아 요리해서 정해진 형식(그릇에 담긴 음식)으로 돌려줍니다. 손님은 주방 안에서 무슨 일이 벌어지는지 몰라도 됩니다. 오직 메뉴판에 적힌 주문 방법과 결과물의 형식만 알면 됩니다. 프로그램끼리도 마찬가지로, 날씨 앱은 기상청 서버 내부 코드를 몰라도 "이 도시의 오늘 날씨를 알려줘"라는 정해진 형식으로 요청(API 호출)만 보내면 원하는 날씨 정보를 돌려받습니다.

🛠 실전 연결
여러분이 만들 여비 계산기에서 영수증 사진 속 글자를 숫자로 읽어내는 부분이 바로 API 호출입니다. "이 이미지를 분석해줘"라는 정해진 형식으로 OCR(글자 인식) 서비스에 요청을 보내면, 그 서비스는 내부에서 어떤 방식으로 글자를 읽어내는지 알려주지 않아도 "인식된 금액: 12,000원"처럼 정해진 형식의 답을 돌려줍니다. Kakao 프록시 사례도 같은 원리입니다. 여러분의 크롬 확장이 카카오 로그인 창을 직접 만들지 않고, 카카오가 미리 정해 놓은 API 규격(이런 정보를 이런 주소로 보내면, 이런 형식으로 로그인 결과를 준다)에 맞춰 요청을 보내기 때문에 별도의 인증 시스템을 처음부터 만들지 않아도 되는 것입니다.

🔍 예시
실제 API 호출은 보통 아래처럼 "주소 + 요청 형식"과 "응답 형식"이 정해진 대화입니다.

요청 (여비 계산기 → 환율 API)
  주소 : GET https://api.exchangerate.example/latest?base=KRW
  응답 :
  {
    "base": "KRW",
    "rates": { "USD": 0.00073, "JPY": 0.107 }
  }

이 요청을 보낼 때 프로그램은 환율 계산이 서버 내부에서 어떻게 이루어지는지 전혀 몰라도 됩니다. 정해진 주소로, 정해진 형식(base=KRW라는 조건)에 맞춰 요청을 보내면, 정해진 형식(rates라는 이름의 숫자 목록)의 응답이 돌아온다는 약속만 지키면 됩니다.

📝 오늘의 한 줄 정리
API는 프로그램끼리 내부 원리를 몰라도 협업할 수 있게 해주는, 미리 정해 놓은 요청과 응답의 대화 규칙입니다.

🙋 초보자가 자주 헷갈리는 점
API를 어떤 실체가 있는 프로그램이나 웹사이트로 착각하기 쉽지만, API는 "물건"이 아니라 "약속(규칙)"입니다. 메뉴판이 음식 그 자체가 아니라 주문하는 방법을 정리한 문서이듯, API도 데이터를 얻는 방법을 정리한 규칙일 뿐이며, 실제로 데이터를 주고받는 통로 역할은 API 뒤에 있는 서버가 담당합니다.

💬 내일 예고
내일은 API와 비슷해 보이지만 정반대 방향으로 움직이는 웹훅(Webhook)을 배웁니다. 손님이 주방에 직접 주문하는 API와 달리, 주방에서 요리가 다 되면 손님에게 먼저 알려주는 방식이 무엇이 다른지 비교해 보겠습니다.
