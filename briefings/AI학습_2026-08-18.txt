📚 오늘의 학습 주제 : 21일차 · Git/GitHub 자동 배포(CI/CD) — 코드를 저장하면 자동으로 반영되는 구조 (2026-08-18)

📌 어제 배운 내용과의 연결
어제는 카카오 프록시를 배포할 때 실제 키 값을 코드에 적지 않고 환경변수로 분리해서 배포 플랫폼 안에만 따로 보관해두는 법을 배웠는데, 오늘은 그렇게 안전하게 정리된 코드를 깃허브(GitHub)에 올리기만 하면 왜 자동으로 실제 서비스까지 반영되는지, 그 뒤에서 돌아가는 구조를 배웁니다.

🎯 오늘 배울 개념
Git/GitHub 자동 배포(CI/CD, Continuous Integration과 Continuous Deployment, 코드를 저장소에 올리면 자동으로 검사하고 실제 서비스에 반영해주는 흐름)란 무엇이며, 사람이 직접 서버에 파일을 옮기던 방식과 무엇이 다른지

━━━━━━━━━━━━━━

어제 금고에 비유했던 건물 관리소를 다시 떠올려 봅시다. 지금까지는 관리소가 열쇠, 즉 환경변수를 보관하는 역할이었다면, 오늘은 그 관리소가 또 하나의 일을 맡습니다. 바로 총무팀 서고에 보관된 업무 매뉴얼 원본, 즉 깃허브 저장소의 코드가 새로 고쳐질 때마다 그 사실을 알아채고, 건물 안 모든 회의실 게시판에 자동으로 새 매뉴얼을 붙여주는 일입니다. 예전 같으면 매뉴얼을 고친 사람이 직접 인쇄해서 각 층을 돌며 게시판을 일일이 갈아 끼워야 했고, 이 과정에서 한 층을 빠뜨리거나 옛날 버전을 잘못 붙이는 실수가 흔했습니다. CI(Continuous Integration, 코드를 새로 올릴 때마다 자동으로 잘 작동하는지 검사하는 과정)는 관리소 직원이 새 매뉴얼을 게시하기 전에 오탈자나 앞뒤가 안 맞는 내용은 없는지 먼저 자동으로 검수하는 단계이고, CD(Continuous Deployment, 검사를 통과한 코드를 자동으로 실제 서비스에 반영하는 과정)는 그 검수를 통과한 매뉴얼을 관리소가 곧바로 모든 게시판에 붙여버리는 단계입니다. 총무팀, 즉 코드를 짜는 사람은 서고의 원본만 고쳐서 제출하면 되고, 검수와 게시는 관리소가 알아서 해주는 것입니다.

🛠 실전 연결
어제 다룬 카카오 프록시 프로젝트를 깃허브 저장소와 Vercel에 미리 연결해두면 이 구조를 그대로 체험할 수 있습니다. 로컬 컴퓨터에서 코드를 고친 뒤 깃허브에 올리기만 하면, Vercel이 저장소의 변경을 즉시 감지해서 새 코드를 내려받고, 빌드(코드를 실제로 실행 가능한 형태로 조립하는 과정)한 뒤, 문제가 없으면 몇 초에서 몇십 초 안에 실제 서비스 주소에 자동으로 반영합니다. 만약 크롬 확장 프로그램의 배경 스크립트가 이 프록시 서버를 호출하도록 만들어져 있다면, 서버 쪽 코드를 고쳐서 올리는 것만으로 크롬 확장도 곧바로 새로운 동작을 하게 되는 것이 바로 이 구조 덕분입니다.

🔍 예시
실제 화면에서는 대략 이런 순서로 진행됩니다. 먼저 로컬 컴퓨터 터미널에서 아래처럼 코드를 저장소에 올립니다.

  git add .
  git commit -m "카카오 콜백 URL 수정"
  git push origin main

이 명령이 끝나는 순간 Vercel 대시보드의 Deployments 화면에 새 배포 항목이 자동으로 나타나고, 상태가 Building(빌드 중)에서 Ready(반영 완료)로 바뀝니다. Ready로 바뀌면 실제 서비스 주소를 새로고침했을 때 방금 고친 내용이 그대로 반영되어 있는 것을 확인할 수 있습니다. 만약 코드에 오류가 있어서 빌드 도중 검사를 통과하지 못하면, 상태가 Ready로 바뀌지 않고 Error로 표시되며 예전 버전이 그대로 유지되므로, 고장 난 매뉴얼이 게시판에 잘못 붙는 일은 애초에 막힙니다.

📝 오늘의 한 줄 정리
CI/CD는 코드를 깃허브에 올리기만 하면 관리소가 대신 검수하고, 문제가 없을 때만 실제 서비스에 자동으로 반영해주는 자동 배포 시스템입니다.

🙋 초보자가 자주 헷갈리는 점
CI(검사)와 CD(반영)를 하나로 뭉뚱그려 "그냥 자동 배포"라고만 이해하는 경우가 많은데, 실제로는 검사를 먼저 통과해야 반영 단계로 넘어가는 두 단계입니다. 또한 자동 배포라고 해서 아무 코드나 검토 없이 올려도 된다는 뜻이 아니라, 사람이 짠 코드의 품질은 여전히 사람 책임이고 CI/CD는 그 코드를 옮기고 확인하는 수고를 대신해줄 뿐이라는 점도 자주 헷갈립니다.

💬 내일 예고
내일은 이렇게 자동으로 배포된 서버가 아니라, 우리가 보고 있는 웹페이지 그 자체에 직접 끼어드는 자동화, 즉 브라우저 확장(Chrome Extension)에서의 자동화를 배웁니다.
