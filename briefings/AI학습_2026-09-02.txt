📚 오늘의 학습 주제 : 심화 11일차 · n8n의 노드 그래프와 IF·Switch·반복 노드, 화면에 갈림길을 직접 그린다는 것 (2026-09-02)

📌 어제 배운 내용과의 연결
어제는 Zapier 안에서 조건에 따라 갈림길을 나누는 Filter와 Paths가 결국 미리 정한 숫자·문자 비교 규칙 하나로 흐름을 멈추거나 두 갈래로 흘려보내는 검사대라는 것을 확인했으니, 오늘은 같은 갈림길을 n8n이라는 도구가 화면 위에 실제 그림으로 어떻게 그려내는지, 그리고 여러 개를 반복해서 처리하는 갈림길까지 살펴봅니다.

🎯 오늘 배울 개념
n8n의 노드 그래프(Node Graph, 각 동작 단계를 상자로 그리고 선으로 이어 흐름 전체를 한눈에 보여주는 화면 구조)와, 그 안에서 갈림길을 만드는 IF 노드(IF Node, 조건이 참인지 거짓인지에 따라 두 갈래로 나누는 상자)·Switch 노드(Switch Node, 여러 조건 중 어디에 해당하는지에 따라 여러 갈래로 나누는 상자), 그리고 목록을 하나씩 꺼내 반복시키는 반복 노드(Loop Node / Split In Batches, 리스트 안의 항목을 한 개씩 꺼내 같은 작업을 되풀이시키는 상자)

━━━━━━━━━━━━━━━━━━━━

어제 우리는 Zapier의 생산 라인을 세로로 한 줄씩 내려가는 목록 화면으로 봤습니다. 트리거 밑에 액션1, 그 밑에 액션2, 그리고 경로(Paths)를 추가하면 화면이 살짝 벌어지며 A라인·B라인 이름표가 붙는 정도였죠. n8n은 이 생산 라인을 아예 공장 전체 배치도(캔버스, Canvas, 노드들을 자유롭게 배치하고 선으로 연결하는 작업 화면)로 펼쳐 놓습니다. 웹훅 상자에서 선이 하나 뻗어 나와 IF 상자로 들어가고, IF 상자에서는 선이 두 갈래로 갈라져 각각 Slack 상자와 Sheets 상자로 들어가는 모습을 화면에서 직접 손으로 그려서 만듭니다. 즉 Zapier가 "이 경로의 조건은 무엇입니까"라고 빈칸을 채우게 했다면, n8n은 "이 갈림길이 실제로 어디로 이어지는지 선을 그으세요"라고 요구하는 셈입니다. 여기에 더해 n8n에는 Zapier의 기본 화면에는 잘 보이지 않는 반복 노드가 있습니다. 공장 비유를 이어가면, 어제 지출 전표 한 장을 검사대에 올려 합격·불합격을 가렸다면, 오늘은 상자 하나에 전표 열 장이 한꺼번에 들어왔을 때 반복 노드가 컨베이어 벨트처럼 전표를 한 장씩 꺼내 검사대(IF 노드) 앞으로 밀어 넣고, 검사가 끝나면 다음 전표를 또 꺼내는 역할을 합니다. Zapier의 Paths는 "전표 한 장이 왔을 때 어디로 보낼지"만 정하지만, n8n의 반복 노드는 "전표 뭉치 전체를 한 장씩 꺼내는 동작 자체"를 별도의 상자로 만들어 준다는 점이 다릅니다.

🛠 실전 연결
여러분의 크롬 확장이 여비 영수증 하나가 아니라 출장 하나에 딸린 영수증 다섯 장을 한꺼번에 긁어서 Kakao 프록시로 넘긴다고 가정해 보겠습니다. Zapier라면 이 다섯 장을 한 번에 처리하는 표준 화면이 마땅치 않아 억지로 나눠 보내야 하지만, n8n에서는 이렇게 그립니다. 웹훅 노드가 영수증 다섯 장이 담긴 목록을 통째로 받고 → 반복 노드가 그 목록에서 영수증을 한 장씩 꺼내고 → IF 노드가 그 한 장의 금액이 10만 원 이상인지 검사하고 → 참이면 Slack 노드로, 거짓이면 Google Sheets 노드로 보낸 뒤 → 다시 반복 노드로 돌아가 다음 영수증을 꺼냅니다. 화면 위에서 이 흐름은 실제로 반복 노드에서 IF 노드로 갔다가 다시 반복 노드로 돌아오는 동그란 선으로 그려집니다. 다만 "영수증 사진을 보고 이게 교통비인지 식비인지 분류해줘" 같은 판단은 여전히 IF 노드의 숫자·문자 비교 규칙으로는 처리할 수 없고, 이 지점에서 노드 하나가 Claude 같은 AI 에이전트를 호출하는 구조로 이어지는데, 이는 3부에서 다룰 내용입니다.

🔍 예시
n8n 캔버스에 위 시나리오를 옮기면 상자와 선이 대략 이렇게 배치됩니다.

  1번 노드 [Webhook]
    이름 : 영수증 목록 수신
    받은 데이터 : [ {user:"홍길동", amount:150000}, {user:"홍길동", amount:35000}, ... 총 5건 ]

  2번 노드 [Loop Over Items]
    입력 : 1번 노드가 받은 목록 전체
    동작 : 목록에서 항목을 1개씩 꺼내 3번 노드로 보냄, 5건 모두 처리될 때까지 반복

  3번 노드 [IF]
    조건식 : {{$json["amount"]}} >= 100000
    참 출력 → 4번 노드로 연결된 선
    거짓 출력 → 5번 노드로 연결된 선

  4번 노드 [Slack] (참일 때)
    채널 : #정산승인
    메시지 : {{$json["user"]}}님이 {{$json["amount"]}}원 정산 승인을 요청했습니다

  5번 노드 [Google Sheets] (거짓일 때)
    시트 : 여비정산_2026
    행 추가 : user, amount 값을 각 열에 매핑

  4번, 5번 노드 모두 → 다시 2번 노드로 선을 연결 (다음 영수증 처리)

여기서 {{$json["amount"]}}처럼 중괄호 두 개로 감싸는 문법을 표현식(Expression, 이전 노드가 만들어낸 데이터 값을 가져와 지금 노드에서 바로 쓰는 방식)이라고 부르며, Zapier에서 마우스로 필드를 클릭해 끌어오던 것을 n8n에서는 이렇게 글자로 직접 지정합니다.

📝 오늘의 한 줄 정리
n8n은 Zapier가 목록 화면 뒤에 숨겨두었던 갈림길과 반복을 IF·Switch·반복 노드라는 상자와 선으로 캔버스 위에 직접 그리게 해주는 도구이며, 그래서 영수증 여러 장처럼 묶음 데이터를 한 장씩 반복 처리하는 흐름까지 눈으로 보며 만들 수 있습니다.

🙋 초보자가 자주 헷갈리는 점
캔버스에 노드를 여러 개 늘어놓기만 하면 자동으로 갈림길이 생긴다고 착각하기 쉽습니다. 실제로 갈림길을 만드는 것은 노드의 개수가 아니라 IF·Switch 노드가 가진 여러 개의 출력 포트(선이 나가는 자리)이며, 단순히 노드 세 개를 나란히 그려 놓았다고 자동으로 나뉘는 것이 아니라 그 사이를 어떤 선으로 잇느냐가 갈림길을 결정합니다. 또한 반복 노드의 반복(같은 작업을 여러 항목에 되풀이하는 것)과 IF·Switch 노드의 분기(하나의 항목을 두 갈래 중 하나로 보내는 것)를 같은 개념으로 혼동하기 쉬운데, 반복은 컨베이어 벨트가 도는 것이고 분기는 벨트 위 한 지점의 갈림길이라는 점에서 서로 다른 역할입니다.

💬 내일 예고
내일은 심화 12일차로, Make(구 Integromat)가 n8n의 노드 그래프와 비슷해 보이면서도 데이터를 낱개가 아니라 번들(Bundle, 여러 항목을 하나로 묶어 함께 이동시키는 데이터 뭉치) 단위로 다루는 시나리오 화면 구조를 n8n의 반복 노드와 비교하며 살펴봅니다.
