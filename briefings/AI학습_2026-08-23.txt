🎯 오늘 배울 개념
자동화(Automation, 사람이 매번 손대지 않아도 정해진 조건에서 정해진 작업이 저절로 실행되게 만드는 것)란 결국 "if 조건문 하나와 그 조건문이 실행하는 코드 한 덩어리"에 지나지 않는다는 것을, 여러분이 이미 가진 실제 코드로 직접 확인하기

━━━━━━━━━━━━━━━━

1일차에 자동화를 "만약 ~하면, 그러면 ~한다"는 규칙이라고 배웠을 때는 이것을 회사의 안내 데스크 센서에 비유했습니다. 오늘은 그 비유를 코드 한 줄로 그대로 옮겨보겠습니다. 안내 데스크 센서가 하는 일은 사실 프로그래밍 언어로 쓰면 이렇게 요약됩니다.

if (손님이_들어왔다) { 직원을_호출한다() }

이 한 줄이 자동화의 전부입니다. 괄호 안의 조건이 트리거이고, 중괄호 안의 실행문이 액션입니다. 여러분의 Kakao 프록시 서버리스 함수도, 크롬 확장의 background.js도, 그리고 지금 이 글을 쓰고 있는 Claude Routines도 결국 이 if문 하나를 얼마나 정교하게, 그리고 얼마나 여러 겹으로 쌓았느냐의 차이일 뿐 본질은 똑같습니다. 다만 실제 자동화 코드는 조건 하나만 확인하고 끝나지 않고, 조건이 참일 때 다시 다른 시스템에 신호를 보내고, 그 시스템이 또 다른 조건을 확인하는 식으로 여러 겹의 if문이 서로 다른 프로그램, 서로 다른 서버에 걸쳐 이어집니다. 오늘부터 심화 단계에서 하려는 것이 바로 이것입니다. 겉으로는 "여비 계산기가 자동으로 채워진다"는 하나의 결과지만, 그 뒤에는 최소 서너 개의 서로 다른 도구에 흩어진 if문들이 순서대로 릴레이를 하고 있다는 것을 실제 코드로 하나씩 확인하는 것입니다.

🛠 실전 연결
오늘 이 글이 만들어진 과정 자체가 좋은 예시입니다. Claude Routines는 매일 정해진 시각에 깨어나서(스케줄링, 6일차) 먼저 GitHub 저장소의 learning-log 브랜치, briefings 폴더를 확인합니다. 이때 실제로 실행되는 것은 대략 이런 조건문입니다. 가장 최근 파일의 일차 번호를 읽어서, 그 값이 25면 심화 1일차로, 25가 아니면 다음 번호로 진행하라는 판단입니다. 이 판단 하나가 오늘 여러분이 지금 읽고 있는 "심화 1일차"라는 제목을 만들어낸 트리거였습니다. 같은 원리가 여비 계산기 쪽에서도 그대로 반복됩니다. 크롬 확장의 background.js는 카카오 로그인 응답을 받을 때마다 다음 조건을 확인합니다. 응답 안에 access_token이 있는가. 있다면 저장하고 content.js에 신호를 보내고, 없다면 재시도 로직으로 넘어갑니다. 결국 이 학습 브리핑 시스템도, 여비 계산기도 겉모습은 완전히 다르지만 뼈대는 똑같은 if문 릴레이라는 것을 알 수 있습니다.

🔍 예시
여러분의 Kakao 프록시 서버리스 함수 안에 실제로 있을 법한 코드를 조건문 중심으로만 뽑아보면 다음과 같습니다.

  export default async function handler(req, res) {
    if (req.method !== 'POST') {
      return res.status(405).end()
    }

    const token = await getKakaoToken(req.body.code)

    if (!token) {
      return res.status(401).json({ error: '로그인 실패' })
    }

    return res.status(200).json({ access_token: token })
  }

이 짧은 코드 안에도 사실 조건문이 두 번 등장합니다. 첫 번째 if는 "POST 요청이 아니면 거절한다"는 트리거 필터이고, 두 번째 if는 "토큰을 못 받았으면 실패로 응답한다"는 예외 처리(23일차에 배울 내용의 씨앗)입니다. 그리고 이 함수 전체가 실행되는 계기, 즉 크롬 확장이 이 주소로 요청을 보내는 순간이 진짜 트리거이고, res.status(200).json(...)으로 응답을 돌려주는 것이 액션입니다.

📝 오늘의 한 줄 정리
자동화는 결국 if 조건문 하나가 여러 도구, 여러 서버에 걸쳐 릴레이하듯 이어진 것일 뿐이며, 그 릴레이를 코드 한 줄 단위로 쪼개서 볼 수 있게 되는 것이 심화 단계의 목표입니다.

🙋 초보자가 자주 헷갈리는 점
자동화 코드를 처음 보면 "이렇게 짧은 코드가 정말 그 복잡한 일을 다 하는 게 맞나" 싶어 불안해지기 쉽습니다. 하지만 실제로 복잡해 보이는 자동화도 뜯어보면 대부분 if문 몇 개와 그 사이를 잇는 API 호출 몇 줄이 전부입니다. 복잡함은 코드 한 덩어리 안에 있는 것이 아니라, 그런 코드 덩어리가 몇 개나 서로 연결되어 있는가, 그 연결 개수에서 나옵니다. 그래서 자동화를 설계할 때는 코드를 얼마나 화려하게 짜는가보다, 조건과 조건 사이의 연결을 얼마나 명확하게 그리는가가 훨씬 중요합니다.
