📚 오늘의 학습 주제 : 심화 10일차 · 멀티스텝 Zap과 조건 분기, 하나의 트리거로 여러 갈래 결과를 만드는 법 (2026-09-01)

📌 어제 배운 내용과의 연결
어제는 트리거 부품 하나와 액션 부품 하나를 뜯어서 그 안에 API 요청 코드가 미리 짜여 있다는 것을 확인했으니, 오늘은 그 부품들을 여러 개 이어 붙이고 중간에 갈림길까지 넣어서 하나의 트리거로 서로 다른 결과를 만드는 방법을 살펴봅니다.

🎯 오늘 배울 개념
멀티스텝 Zap(Multi-Step Zap, 트리거 하나에 액션 단계를 순서대로 여러 개 이어 붙인 자동화)과, Filter·Paths(조건에 맞지 않으면 실행을 멈추거나, 조건에 따라 서로 다른 갈래로 나눠 실행하는 조건 분기 기능)

━━━━━━━━━━━━━━━━━━━━

어제 조립식 미니 공장 키트의 부품 하나하나가 "API 호출 코드 + 빈칸"이라는 것을 확인했다면, 오늘은 그 부품들을 실제 공장의 생산 라인처럼 한 줄로 세워보겠습니다. 원단이 들어오면(트리거) → 재단하고(액션1) → 도색하고(액션2) → 포장하는(액션3) 것처럼, Zap도 트리거 뒤에 액션 블록을 순서대로 여러 개 붙일 수 있습니다. 이것이 멀티스텝 Zap입니다. 그런데 실제 생산 라인에는 품질 검사대가 하나 더 있습니다. 검사대에서 합격 판정을 받은 제품만 다음 공정(포장)으로 넘어가고, 불합격 판정을 받은 제품은 아예 라인 밖으로 빠지거나(폐기) 재작업 라인으로 옮겨집니다. Zapier에서 이 검사대 역할을 하는 것이 두 가지입니다. 하나는 필터(Filter by Zapier, 조건에 맞지 않으면 그 시점에서 Zap 전체 실행을 완전히 멈추는 기능)이고, 다른 하나는 경로(Paths by Zapier, 조건에 따라 A라인 또는 B라인 중 한 갈래로 흘려보내 각자 다른 액션을 실행시키는 기능)입니다. 필터는 "불합격이면 폐기"이고, 경로는 "합격이면 포장 라인, 불합격이면 재작업 라인"인 셈입니다. 중요한 것은 이 검사대의 판정 기준이 사람이 매번 눈으로 보고 정하는 것이 아니라, "금액이 10만 원 이상인가" 같은 미리 정해둔 숫자·문자 비교 규칙 하나뿐이라는 점입니다. 이 규칙에 해당하지 않는 애매한 판단은 검사대가 아예 처리하지 못합니다.

🛠 실전 연결
여러분의 여비 계산기와 Kakao 프록시를 이 생산 라인에 그대로 얹어보면 이렇습니다. 1단계 트리거는 Kakao 프록시가 정산 완료 응답을 보낼 때 울리는 웹훅입니다. 2단계는 방금 배운 경로(Paths) 블록으로, 정산 금액이 10만 원 이상인지 아닌지에 따라 갈림길을 만듭니다. A라인(10만 원 이상)은 팀장 결재가 필요하니 Slack으로 승인 요청 메시지를 보내는 액션으로 이어지고, B라인(10만 원 미만)은 결재 없이 바로 Google Sheets 정산 시트에 행을 추가하는 액션으로 이어집니다. 크롬 확장은 이 구조에서 트리거를 발생시키는 시작점 역할만 하고, 그 이후에 갈림길을 나누는 판단은 전부 Zapier 화면 안에서 처리됩니다. 다만 "이 지출이 출장비인지 회식비인지 애매한데 영수증 사진을 보고 판단해줘" 같은 요청은 숫자 비교 규칙이 아니므로 경로 블록이 처리할 수 없고, 이런 유연한 판단이 필요한 지점이 바로 3부에서 다룰 Claude Routines 같은 AI 에이전트가 검사대 자리에 대신 들어와야 하는 지점입니다.

🔍 예시
Zapier 화면에서 "정산 금액에 따라 결재 요청과 시트 기록을 나누는" Zap을 멀티스텝으로 구성하면 대략 이렇게 채워집니다.

  1단계 [트리거]
    앱 : Webhooks by Zapier
    이벤트 : Catch Hook
    받은 샘플 데이터 : user_name=홍길동, amount=150000, date=2026-09-01

  2단계 [Paths by Zapier 추가]
    경로 이름 A : 고액 결재 필요
    조건(Rule) : amount 크거나같음(Greater than or equal to) 100000
    경로 이름 B : 즉시 기록
    조건(Rule) : amount 작음(Less than) 100000

  3단계 [경로 A의 액션]
    앱 : Slack
    이벤트 : Send Channel Message
    채널 : #정산승인
    메시지 : 홍길동님이 150000원 정산 승인을 요청했습니다

  4단계 [경로 B의 액션]
    앱 : Google Sheets
    이벤트 : Create Spreadsheet Row
    스프레드시트 : 여비정산_2026
    열 매핑 : A열←user_name, B열←amount, C열←date

저장 버튼을 누르면 Zapier 내부에서는 2단계에서 amount 값을 조건식으로 비교한 뒤, 참이면 3단계 코드 블록(Slack API 호출)만 실행하고 거짓이면 4단계 코드 블록(Sheets API 호출)만 실행하도록 분기 처리가 자동으로 짜여 들어갑니다. 두 액션 블록의 코드는 이미 각자 완성되어 있고, 여러분은 그 갈림길의 숫자 기준 하나만 정해준 것입니다.

📝 오늘의 한 줄 정리
멀티스텝 Zap은 트리거 뒤에 액션을 여러 개 순서대로 이어 붙인 것이고, Filter와 Paths는 그 순서 중간에 미리 정한 숫자·문자 비교 규칙 하나로 흐름을 멈추거나 갈림길을 나누는 검사대입니다.

🙋 초보자가 자주 헷갈리는 점
Filter와 Paths를 같은 것으로 헷갈리기 쉽습니다. Filter는 조건에 맞지 않으면 그 뒤의 액션이 전부 실행되지 않고 Zap이 조용히 끝나버리는 것이고, Paths는 조건에 맞지 않아도 Zap이 멈추는 것이 아니라 다른 경로의 액션으로 대신 흘러가는 것입니다. 즉 Filter 뒤에는 길이 하나뿐이라 막히면 그냥 끝이고, Paths 뒤에는 길이 최소 두 개라서 막힌 것처럼 보여도 실제로는 다른 길로 가고 있는 것입니다.

💬 내일 예고
내일은 심화 11일차로, Zapier와 다르게 여러 도구를 하나의 화면 안에서 노드(마디)로 직접 그려 연결하는 n8n이 조건 분기와 반복 실행을 어떤 화면 구조로 처리하는지, Zapier의 Paths와 비교하며 실제 노드 그래프 수준까지 살펴봅니다.
