📚 오늘의 학습 주제 : 20일차 · 환경변수(Environment Variable)와 보안 — 비밀정보를 코드에 넣지 않는 이유 (2026-08-17)

📌 어제 배운 내용과의 연결
어제는 카카오 프록시 코드 예시에서 process.env.KAKAO_CLIENT_ID라는 낯선 표현이 등장했는데, 오늘은 바로 그 process.env가 무엇이고 왜 클라이언트 아이디를 코드에 직접 적지 않고 이렇게 돌려서 불러오는지를 배웁니다.

🎯 오늘 배울 개념
환경변수(Environment Variable, 코드 밖에 따로 보관해두고 실행할 때만 불러와 쓰는 값)란 무엇이며, 비밀번호나 인증키 같은 값을 코드 안에 직접 적지 않고 환경변수로 분리해야 하는 이유

━━━━━━━━━━━━━━

어제 공유 회의실에 비유했던 서버리스 함수를 떠올려 보면, 회의실 직원(함수)이 일을 처리하려면 가끔 특정 시스템의 출입카드나 비밀번호가 필요할 때가 있습니다. 이때 초보자가 흔히 저지르는 실수가, 그 출입카드 비밀번호를 아예 업무 매뉴얼(코드) 첫 페이지에 손글씨로 적어두는 것입니다. 매뉴얼은 누구나 복사해서 돌려볼 수 있고, 심지어 깃허브(GitHub)처럼 전 세계에 공개된 저장소에 그대로 올라가기도 하니, 비밀번호를 코드에 적는 순간 그 비밀번호는 더 이상 비밀이 아니게 됩니다. 환경변수는 이 비밀번호를 매뉴얼에 적는 대신, 회의실 벽에 붙은 잠금 금고에 넣어두는 것과 같습니다. 매뉴얼에는 "출근하면 금고에서 열쇠를 꺼내 쓴다"는 지침만 적혀 있고, 실제 열쇠 값은 그 금고를 관리하는 건물 관리소(서버리스 플랫폼이나 실행 환경)가 따로 보관합니다. 그래서 코드(process.env.KAKAO_CLIENT_ID)는 "이 이름표가 붙은 금고 칸을 열어서 값을 꺼내 써라"라는 지시일 뿐이고, 실제 값이 무엇인지는 코드만 봐서는 절대 알 수 없습니다.

🛠 실전 연결
어제 다룬 카카오 프록시를 실제로 배포한다면, KAKAO_CLIENT_ID와 KAKAO_CLIENT_SECRET 두 값을 코드 파일 안에 적는 대신 Vercel 프로젝트의 환경변수 설정 화면에 따로 등록해두게 됩니다. 로컬 컴퓨터에서 테스트할 때는 .env라는 별도 파일에 이 값들을 적어두고, 이 파일은 .gitignore(깃허브에 절대 올리지 말라고 지정하는 목록)에 등록해서 실수로라도 저장소에 함께 올라가지 않도록 막습니다. 즉 코드는 그대로 깃허브에 공개해도 괜찮지만, 금고 열쇠에 해당하는 실제 값은 깃허브 바깥, 배포 플랫폼 안에만 존재하게 만드는 것이 핵심입니다.

🔍 예시
로컬 개발용 .env 파일은 대략 이런 모습입니다.

  KAKAO_CLIENT_ID=a1b2c3d4e5f6
  KAKAO_CLIENT_SECRET=9z8y7x6w5v

그리고 .gitignore 파일 안에는 이 파일이 절대 깃허브에 올라가지 않도록 아래 한 줄을 적어둡니다.

  .env

Vercel 대시보드에서는 코드를 배포한 뒤 프로젝트 설정(Settings) 메뉴의 Environment Variables 화면에 들어가서, Key 칸에 KAKAO_CLIENT_ID, Value 칸에 실제 발급받은 키 값을 입력하고 저장하면, 어제 본 코드의 process.env.KAKAO_CLIENT_ID가 실행되는 순간 그 값을 자동으로 불러다 씁니다. 코드 파일 어디를 봐도 실제 키 값은 적혀 있지 않습니다.

📝 오늘의 한 줄 정리
환경변수는 비밀번호나 인증키를 코드라는 공개된 매뉴얼에 적지 않고, 배포 플랫폼이 따로 관리하는 잠긴 금고에 넣어두었다가 실행할 때만 꺼내 쓰는 방식입니다.

🙋 초보자가 자주 헷갈리는 점
.env 파일 자체를 깃허브에 올려버리면 환경변수를 쓰는 의미가 없어지는데, 초보자는 종종 .gitignore에 .env를 등록하는 것을 잊고 실수로 함께 올려버립니다. 또한 환경변수는 코드를 안전하게 만들어주는 장치일 뿐 코드를 대신 짜주지는 않는다는 점, 즉 "이 값을 어디서 꺼내 쓸지" 코드에 지정하는 일 자체는 여전히 사람이 해야 한다는 점도 자주 헷갈립니다.

💬 내일 예고
내일은 이렇게 환경변수까지 안전하게 갖춘 코드를 저장소에 올리기만 하면 자동으로 배포까지 이어지는 구조, 즉 Git/GitHub 자동 배포(CI/CD)를 배웁니다.
