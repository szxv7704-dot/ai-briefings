📚 오늘의 학습 주제 : 19일차 · 서버리스 함수(Serverless Function) — 서버 없이 코드를 실행한다는 것의 의미 (2026-08-16)

🗺 이번 파트에서 배울 것
1부에서 자동화의 개념을, 2부에서 노코드 도구를, 3부에서 AI 에이전트를 배웠다면, 4부는 그 판단 로직을 사람이 직접 코드로 짜서 돌리는 실전 영역입니다. 서버리스 함수(Serverless Function)로 서버 관리 없이 코드를 실행하는 법부터, 환경변수(Environment Variable)로 비밀정보를 안전하게 다루는 법, 코드를 저장소에 올리면 자동으로 반영되는 배포(CI/CD) 구조, 마지막으로 크롬 확장처럼 브라우저 안에서 직접 개입하는 자동화까지 이어집니다. 지금까지가 '무엇을, 언제' 시킬지를 배우는 단계였다면, 4부는 그 지시를 실제로 실행하는 코드의 뼈대를 들여다보는 단계입니다.

📌 어제 배운 내용과의 연결
어제는 노코드 도구와 에이전트가 결국 판단이 필요 없는 구간은 노코드가, 판단이 필요한 구간은 에이전트가 나누어 맡는 협업 관계라는 것을 정리했으니, 오늘은 4부의 시작으로 그 판단 로직을 사람이 직접 코드로 짰을 때 그 코드를 어디서, 어떻게 실행할지를 다루는 서버리스 함수 개념부터 시작합니다.

🎯 오늘 배울 개념
서버리스 함수(Serverless Function)란 무엇이며, 이름과 달리 왜 "서버가 아예 없다"는 뜻이 아니라 "내가 서버를 사고 켜고 관리할 필요가 없다"는 뜻인지, 그리고 이것이 자동화에서 왜 중요한지

━━━━━━━━━━━━━━

서버리스(Serverless)라는 이름 때문에 흔히 오해하는 것이, 정말로 서버가 사라진다는 뜻이라는 착각입니다. 서버는 여전히 어딘가에 존재하지만, 그 서버를 사는 것도, 24시간 켜두는 것도, 고장 나면 고치는 것도 내가 아니라 클라우드 회사가 대신 맡아준다는 뜻입니다. 지금까지 우리는 비서(에이전트)가 일할 사무실(하네스)이 필요하다고 배웠는데, 보통 사무실은 통째로 임대하면 아무도 없는 시간에도 월세와 전기세가 계속 나갑니다. 서버리스 함수는 이 사무실을 통째로 빌리는 대신, 회의가 잡힐 때만 잠깐 문이 열리는 공유 회의실을 쓰는 것과 같습니다. 손님(요청, Request)이 초인종을 누르는 그 순간에만 회의실 조명이 켜지고 담당 직원인 함수(Function, 정해진 입력을 받아 정해진 동작을 하고 나면 곧바로 끝나는 코드 한 뭉치)가 나와 정해진 일을 처리한 뒤, 회의가 끝나면 조명도 꺼지고 요금도 그 몇 분만 청구됩니다. 이렇게 요청이 들어올 때만 잠깐 깨어나 함수를 실행하고 끝나면 다시 잠드는 방식이라서, 코드를 짜는 사람은 회의실 건물 자체가 아니라 회의실 안에서 벌어질 그 짧은 업무 하나만 준비하면 됩니다.

🛠 실전 연결
학습자 여러분의 Kakao 프록시 서버가 좋은 예입니다. 만약 이 프록시가 하루 종일 끊임없이 요청이 몰리는 서비스라면 계속 켜둘 서버 한 대를 빌리는 편이 나을 수 있지만, 실제로는 카카오 인증이나 API 호출이 필요한 그 순간에만 잠깐 작동하고 나머지 시간에는 쉬는 구조에 가깝습니다. 이런 경우 서버를 통째로 켜두는 대신 Vercel이나 AWS Lambda 같은 서버리스 함수로 옮기면, 요청이 없는 시간에는 요금이 전혀 나가지 않고 트래픽이 갑자기 몰려도 회의실이 자동으로 여러 개 열리듯 알아서 늘어나 감당합니다. 즉 판단 로직 자체는 그대로 두되, 그 로직을 담아두는 사무실의 형태만 통째 임대에서 쓴 만큼 계산으로 바꾸는 선택인 셈입니다.

🔍 예시
Vercel 같은 서버리스 플랫폼에 카카오 프록시용 파일을 하나 올린다고 하면, api 폴더 아래 kakao_proxy.js라는 파일 하나만 만들면 됩니다. 대략 이런 모습입니다.

  export default async function handler(req, res) {
    const code = req.query.code;
    const response = await fetch("https://kauth.kakao.com/oauth/token", {
      method: "POST",
      body: new URLSearchParams({
        grant_type: "authorization_code",
        client_id: process.env.KAKAO_CLIENT_ID,
        code: code,
      }),
    });
    const data = await response.json();
    res.status(200).json(data);
  }

이 파일을 깃허브 저장소에 올리기만 하면, 서버를 따로 켜거나 도메인을 연결하는 작업 없이도 곧바로 요청을 받을 수 있는 함수 하나가 완성됩니다. 요청이 없을 때는 이 함수가 아예 실행되지 않아 요금도 0원이고, 요청이 오는 그 순간에만 켜져서 응답하고 다시 사라집니다.

📝 오늘의 한 줄 정리
서버리스 함수는 서버가 없는 것이 아니라, 서버를 사고 켜고 고치는 관리 업무를 클라우드에 맡기고 나는 요청이 올 때만 실행될 코드 한 뭉치만 준비해두는 방식입니다.

🙋 초보자가 자주 헷갈리는 점
서버리스라는 이름 때문에 이제 서버 지식이 전혀 필요 없다고 생각하기 쉽지만, 실제로는 서버를 사고 켜고 고치는 관리 업무만 사라진 것이지 어떤 요청에 어떤 응답을 줄지 정하는 로직은 여전히 내가 짜야 합니다. 또한 서버리스는 항상 더 저렴하다고 오해하기 쉬운데, 요청이 매우 많고 꾸준한 서비스라면 오히려 24시간 켜둔 서버 한 대를 쓰는 편이 더 쌀 수도 있어서, 트래픽 패턴에 따라 유불리가 갈립니다.

💬 내일 예고
내일은 오늘 코드 예시에 등장한 process.env.KAKAO_CLIENT_ID가 무엇인지, 즉 환경변수(Environment Variable)로 비밀정보를 코드에 직접 적지 않고 안전하게 다루는 이유를 배웁니다.
