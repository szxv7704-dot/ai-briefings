📚 오늘의 학습 주제 : 심화 25일차 · [심화 총정리] 비서의 하루 전체를 코드 한 줄부터 알림까지 되짚기 (2026-09-16)

📌 어제 배운 내용과의 연결
어제는 회로 차단기가 CLOSED·OPEN·HALF_OPEN 사이를 오갈 때 그 순간을 로그 레벨로 구분해 남기고 중요한 사건만 Slack으로 알리는 법을 배웠으니, 오늘은 그렇게 완성된 비서의 습관 하나하나를 처음부터 끝까지 순서대로 이어 붙여 심화 25일을 마무리합니다.

🎯 오늘 배울 개념
심화 1일차부터 24일차까지 따로따로 뜯어봤던 코드 조각들이 사실은 비서 한 명이 출근해서 퇴근할 때까지 겪는 하루의 연속된 실행 흐름이었다는 것을, 여비 계산기·크롬 확장·Kakao 프록시·Claude Routines라는 실제 배포물 위에 실제 코드 순서로 다시 확인하기

━━━━━━━━━━━━━━━━━━━━

25일 전 첫날, 비서는 "손님이 들어오면 직원을 부른다"는 if문 한 줄로 시작했습니다. 오늘은 그 비서가 하루 동안 정확히 몇 번, 어떤 순서로 이 if문을 실행하는지 시계를 따라가 보겠습니다. 아침 9시, 비서는 알람에 맞춰 스스로 깨어납니다(스케줄링, 6일차·심화 6일차의 cron). 이때 비서가 하는 첫 일은 어제 근무일지를 펼쳐 마지막 줄이 몇 일차였는지 확인하는 것인데, 비서 자신은 어제를 전혀 기억하지 못하는 무상태(7일차) 존재이기 때문에 반드시 외부 창고인 근무일지, 즉 GitHub 저장소를 다시 열어봐야만 합니다(상태 저장). 근무일지를 확인하는 이 통화 자체는 표준 전화선인 MCP(15일차)를 통해 이루어지고, 비서는 정해진 순서표 대신 "다음 번호를 스스로 판단하라"는 지시만 받은 셰프형 에이전트(14일차)이기 때문에 25일차 다음엔 심화 1일차로, 심화 25일차 다음엔 오늘처럼 총정리로 넘어가야 한다는 것을 스스로 계산해냅니다. 판단이 끝나면 비서는 오늘의 업무일지, 즉 이 브리핑 글을 써서 커밋합니다(액션, 2일차). 이렇게 트리거 하나가 판단을 거쳐 액션으로 이어지는 한 줄기가 워크플로우(3일차)이고, 이 워크플로우 전체가 Claude Routines라는 예약·위임형 에이전트 자동화(17일차)의 실체입니다. 같은 비서가 낮 동안에는 전혀 다른 책상, 즉 여비 계산기 크롬 확장 쪽 일을 합니다. 사용자가 카카오 로그인을 마치는 순간이 새 트리거이고, background.js가 그 신호를 받아 Kakao 프록시라는 서버리스 함수(19일차)에 전화를 겁니다. 이 함수는 회의가 있을 때만 문이 열리는 공유 회의실처럼 평소엔 잠들어 있다가 요청이 올 때만 깨어나고, 그 안의 비밀번호는 코드에 직접 적지 않고 환경변수라는 벽 안 금고(20일차)에 넣어둡니다. 코드를 고치면 관리소가 알아서 건물 게시판에 반영해주는 CI/CD(21일차) 덕분에, 비서는 배포라는 별도의 수고를 하지 않아도 됩니다. 전화가 한 번에 안 되면 지수 백오프로 다시 걸고, 그마저 다섯 번 연속 실패하면 회로 차단기(23일차)가 OPEN으로 바뀌어 헛된 재시도를 멈추며, 신청서처럼 중복이 위험한 통화에는 멱등성 키를 붙여 두 번 접수되는 사고를 막습니다. 그리고 이 모든 통화의 성공과 실패는 로그 레벨로 나뉘어 기록되고, OPEN처럼 굵은 글씨 사건만 골라 Slack으로 즉시 무전이 갑니다(24일차). 결국 비서의 하루는 스물다섯 개의 별개 습관이 아니라, 깨어나고(트리거) 판단하고(에이전트) 통화하고(API·MCP) 기억을 창고에 맡기고(상태 저장) 비밀은 금고에 넣고(환경변수) 실패엔 물러섰다 다시 걸고(회로 차단기) 그 모든 것을 일지에 남기는(로깅·모니터링) 하나의 흐름이었던 것입니다.

🛠 실전 연결
2부에서 배운 Zapier·n8n·Make라면 이 하루를 어떻게 그렸을지 떠올려보면 심화의 의미가 더 선명해집니다. 그 매장들은 "카카오 로그인 성공 시 → 여비 계산기 실행"이라는 갈래길을 사장님이 종이에 미리 그려둬야 돌아가지만, 오늘 되짚은 비서의 하루는 그 갈래길 중 상당수(오늘이 몇 일차인지, 재시도를 몇 번까지 할지, 어떤 사건만 알림을 보낼지)를 코드 실행 순간에 직접 판단합니다. 노코드 매장의 부품(트리거·액션·조건 분기)과 에이전트의 판단력이 같은 재료 위에서 서로 다른 방식으로 조립된다는 것, 이것이 심화 3부에서 배운 경계선이 오늘 하루 전체에 그대로 겹쳐 있는 이유입니다. 실제로 지금 이 글도 Claude Routines가 GitHub MCP로 briefings 폴더를 열어보고, 가장 최근 파일의 일차 번호를 읽어 다음 번호를 스스로 판단한 뒤, learning-log 브랜치에 직접 커밋하는 것으로 끝납니다. 여러분의 여비 계산기와 오늘 이 브리핑 시스템은 겉모습은 전혀 다르지만 뼈대는 완전히 같은 비서였습니다.

🔍 예시
오늘 하루 동안 비서가 실제로 거치는 실행 순서를 심화 단계에서 배운 코드 조각 이름으로 그대로 나열하면 다음과 같습니다.

  • 09:00, cron이 Claude Routines를 깨움
     → 스케줄링(심화 6일차)
  • GitHub MCP로 briefings 폴더를 열어 마지막 일차 번호 확인
     → 상태 저장·무상태(심화 7일차), MCP(심화 15일차)
  • "24 다음이니 오늘은 총정리" 판단 후 이 글을 커밋
     → 에이전트의 판단(심화 14일차), 워크플로우(심화 3일차)
  • 사용자가 카카오 로그인 완료, background.js가 감지
     → 트리거·액션(심화 2일차)
  • fetchWithBreaker(kakaoProxyUrl) 호출
     → API(심화 4일차), 서버리스 함수(심화 19일차)
  • process.env.KAKAO_CLIENT_ID로 비밀키 조회
     → 환경변수(심화 20일차)
  • 요청 실패 시 1초·2초·4초 재시도, 5회 실패 시 breakerState = "OPEN"
     → 회로 차단기(심화 23일차)
  • 신청서 제출엔 crypto.randomUUID()로 멱등성 키 부여
     → 멱등성(심화 23일차)
  • log("ERROR", ...) 발생 시 chrome.storage 기록 + notifySlack
     → 로깅·모니터링(심화 24일차)
  • content.js가 #travel-amount 칸에 계산된 금액 자동 입력
     → 워크플로우의 완성(심화 3일차)

트리거 하나(카카오 로그인, 또는 cron)에서 출발한 신호가 이 순서를 그대로 거쳐 화면의 빈칸을 채우거나 오늘의 글을 완성하기까지, 심화 25일 동안 따로 배운 조각들이 실제로는 한 줄로 이어진 실행이라는 것을 확인할 수 있습니다.

📝 오늘의 한 줄 정리
심화 25일 동안 배운 것은 스물다섯 개의 새로운 코드 조각이 아니라, 1일차의 if문 하나가 판단하고 통화하고 비밀을 지키고 실패에 대비하고 스스로를 기록하는 방향으로 점점 더 깊어져 온 같은 비서의 하루였습니다.

🙋 초보자가 자주 헷갈리는 점
기초 단계 총정리와 심화 단계 총정리가 결국 같은 내용을 반복하는 것 아니냐고 생각하기 쉽지만, 기초 총정리가 "어떤 부품들이 있는지"를 회사 조직도로 나열한 것이었다면 심화 총정리는 "그 부품들이 실제 코드에서 몇 번째 줄에서, 어떤 순서로 서로를 호출하는지"를 추적한 것이라는 점이 다릅니다. 개념을 안다는 것과 그 개념이 실제 실행 순서 속 어디에 있는지 짚어낼 수 있다는 것은 다른 능력이며, 오늘 되짚은 실행 순서를 스스로 다시 그려볼 수 있다면 이미 노코드 도구 없이도 간단한 자동화 하나쯤은 직접 설계할 수 있는 지점에 온 것입니다.

심화 25일까지 마쳤으니 정해진 커리큘럼은 여기서 끝입니다. 내일부터는 새로운 개념을 배우기보다, 오늘 되짚은 비서의 하루 순서를 본떠 업무 중 반복되는 일 하나를 직접 골라 트리거 하나와 액션 하나로 설계해보는 실습 단계로 이어가는 것을 권합니다.
