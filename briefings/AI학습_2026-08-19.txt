📚 오늘의 학습 주제 : 22일차 · 브라우저 확장(Chrome Extension)에서의 자동화 — 웹페이지에 개입하는 자동화 (2026-08-19)

📌 어제 배운 내용과의 연결
어제는 코드를 깃허브에 올리기만 하면 관리소가 알아서 검수하고 서버 쪽 게시판에 자동으로 반영해주는 CI/CD 구조를 배웠는데, 오늘은 그 게시판이 아니라 직원 각자가 지금 눈으로 보고 있는 책상 위 문서, 즉 웹페이지 자체에 직접 끼어드는 크롬 확장(Chrome Extension) 자동화를 배웁니다.

🎯 오늘 배울 개념
크롬 확장(Chrome Extension, 브라우저에 설치해서 특정 기능을 더해주는 작은 프로그램)이 어떻게 사용자가 보고 있는 웹페이지 안으로 직접 들어가 내용을 읽거나 바꾸는지, 그리고 화면 위에서 일하는 콘텐츠 스크립트(Content Script)와 화면 뒤에서 항상 대기하는 백그라운드 스크립트(Background Script)가 어떻게 역할을 나누어 맡는지

━━━━━━━━━━━━━━━━━━━━

지금까지 CI/CD 이야기 속 관리소는 총무팀 서고의 매뉴얼을 고쳐서 건물 전체 게시판에 붙여주는 역할이었습니다. 이 방식은 힘이 세지만 한 가지 한계가 있는데, 관리소가 손댈 수 있는 곳은 어디까지나 우리 회사가 소유한 게시판, 즉 우리가 직접 만든 서버와 웹사이트뿐이라는 점입니다. 직원이 지금 책상 위에 펼쳐 놓은 문서가 옆 회사(카카오, 은행, 사내 인트라넷 등)가 만든 문서라면 관리소는 그 문서에 손댈 권한이 없습니다. 크롬 확장(Chrome Extension)은 이 한계를 넘어서기 위한 도구로, 관리소 직원을 보내는 대신 각 직원 책상 옆에 개인 비서 한 명을 붙여주는 방식이라고 생각하면 됩니다. 이 개인 비서는 두 가지 얼굴을 갖고 있습니다. 하나는 콘텐츠 스크립트(Content Script, 사용자가 보고 있는 웹페이지 안에 직접 들어가 그 페이지의 글자와 버튼(DOM, Document Object Model, 웹페이지의 구조와 내용을 컴퓨터가 다룰 수 있는 형태로 표현한 것)을 읽거나 바꾸는 코드)로, 직원이 어떤 문서를 펼치는 바로 그 순간 문서 옆에 나타나 형광펜으로 밑줄을 긋거나 빈칸에 메모를 대신 적어 넣는 역할을 합니다. 다른 하나는 백그라운드 스크립트(Background Script, 화면에는 보이지 않지만 브라우저가 켜져 있는 동안 항상 대기하며 이벤트를 처리하는 코드)로, 비서가 사무실 뒤편 대기실에 앉아 전화(외부 서버 요청)를 받거나 여러 창을 오가며 필요한 정보를 기억해두는 역할을 합니다. 두 얼굴이 나뉘어 있는 이유는 명확합니다. 문서 위에 직접 손을 대는 콘텐츠 스크립트는 그 문서, 즉 특정 웹페이지가 열려 있을 때만 존재할 수 있지만, 전화를 받고 여러 창을 넘나들며 기억을 유지하는 일은 문서 하나에 매여 있으면 안 되기 때문입니다.

🛠 실전 연결
여러분이 만든 크롬 확장이 바로 이 두 얼굴 구조를 그대로 쓰고 있습니다. 어제 이야기한 대로 백그라운드 스크립트는 대기실에 앉아 카카오 로그인이 끝났다는 신호를 받으면 Kakao 프록시 서버에 접속해 access_token을 받아오는 전화 응대 역할을 하고, 콘텐츠 스크립트는 사내 출장신청 페이지가 화면에 뜨는 순간 그 페이지의 여비 입력란을 찾아 여비 계산기가 미리 계산해둔 국내·해외·당일 출장 금액을 자동으로 채워 넣는 형광펜 역할을 합니다. 즉 어제 배운 CI/CD가 여러분이 만든 서버 코드를 자동으로 반영하는 이야기였다면, 오늘 배운 크롬 확장은 그렇게 반영된 서버의 계산 결과를 다시 다른 회사의 웹페이지 안으로 직접 밀어 넣어주는 마지막 한 걸음인 셈입니다.

🔍 예시
크롬 확장은 최소 세 개의 파일로 이루어집니다. 먼저 어떤 페이지에서 어떤 권한으로 동작할지 브라우저에 미리 알려주는 설정 파일인 manifest.json이 있습니다.

  {
    "manifest_version": 3,
    "name": "여비 계산기 자동입력",
    "permissions": ["storage"],
    "content_scripts": [
      { "matches": ["https://intranet.jbe.go.kr/travel/*"], "js": ["content.js"] }
    ],
    "background": { "service_worker": "background.js" }
  }

문서 위에 형광펜을 긋는 content.js는 이렇게 생겼습니다.

  const amountField = document.querySelector("#travel-amount");
  chrome.storage.local.get("calculatedAmount", (result) => {
    amountField.value = result.calculatedAmount;
  });

대기실에서 전화를 받는 background.js는 이렇게 생겼습니다.

  chrome.runtime.onMessage.addListener((message) => {
    if (message.type === "KAKAO_LOGIN_DONE") {
      fetch("https://kakao-proxy.vercel.app/api/token")
        .then((res) => res.json())
        .then((data) => chrome.storage.local.set({ accessToken: data.access_token }));
    }
  });

manifest.json의 matches에 적어둔 주소의 페이지가 열릴 때만 content.js가 자동으로 끼어들고, background.js는 그 페이지가 열려 있지 않아도 항상 대기하다가 로그인 완료 메시지를 받으면 카카오 프록시를 호출합니다.

📝 오늘의 한 줄 정리
크롬 확장은 서버가 아니라 사용자가 지금 보고 있는 웹페이지 안으로 직접 들어가는 자동화이며, 화면 위 문서에 손을 대는 콘텐츠 스크립트와 뒤에서 항상 대기하는 백그라운드 스크립트가 역할을 나누어 맡는다.

🙋 초보자가 자주 헷갈리는 점
콘텐츠 스크립트는 해당 웹페이지가 열려 있을 때만 잠깐 실행되고 페이지를 닫으면 사라지는 반면, 백그라운드 스크립트는 특정 페이지에 묶여 있지 않고 브라우저가 켜져 있는 동안 계속 대기한다는 차이를 헷갈리기 쉽습니다. 또한 크롬 확장이 아무 웹페이지에나 마음대로 개입할 수 있다고 오해하기 쉬운데, 실제로는 manifest.json의 matches와 permissions에 미리 적어둔 범위 안에서만, 그것도 사용자가 설치할 때 승인한 권한 안에서만 동작할 수 있습니다.
